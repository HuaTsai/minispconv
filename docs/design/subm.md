# Design note：SubM 的參數空間

> 對應 `src/minispconv/oracle.py` 中 `build_rulebook` 的 `subm` 分支，以及未來的
> `SubMConv3d`。這份文件寫**原理與參數約束的推導** —— 它不隨迴圈怎麼寫而變。

---

## SubM 與規則卷積只差一件事

兩者共用同一條配對式：

```
in_pos = out_pos · s − p + k · d        k ∈ {0, …, ks−1}
保留條件：in_pos 是 active 的
```

差別**只在輸出座標集合從哪裡來**：

| | 輸出座標集合 | 誰決定 |
| --- | --- | --- |
| 規則卷積 | 由 `out_spatial_shape()` 算出的稠密網格，逐格試，有配到就 active | 公式 + 資料 |
| SubM | **就是輸入的 active 集合**，直接指定 | 定義 |

`build_rulebook` 的 if/else 只做這一件事，其餘完全共用。這個結構本身就是論述：
**SubM 不是另一種卷積，是同一種卷積換了輸出定義域。**

---

## 它為什麼存在：submanifold dilation

9×9 網格，兩個相鄰點 `(4,4), (4,5)`，`ks=3, p=1, s=1`，跑規則卷積。輸出的 active 集
是所有跟某個輸入點 Chebyshev 距離 ≤ 1 的格子，也就是 bounding box 各向外擴一圈。
把輸出餵回去再跑一層，手算：

```
第 0 層：rows 4..4, cols 4..5           →  1 × 2 =  2
第 1 層：rows 3..5, cols 3..6           →  3 × 4 = 12
第 2 層：rows 2..6, cols 2..7           →  5 × 6 = 30
第 3 層：rows 1..7, cols 1..8           →  7 × 8 = 56
第 4 層：rows 0..8, cols 0..8（撞牆）    →  9 × 9 = 81
```

**四層之後整張圖全滿。** 稀疏卷積唯一的優勢 —— 只計算 active 點 —— 在第四層完全消失，
而且效能還輸給稠密卷積，因為多付了 hash 表與 gather/scatter 的錢。

真實 LiDAR 點雲更糟：點本來就散佈在整個場景，每層向外長一格，很快每個 voxel 都 active。

SubM 的同一個數列是 `2 → 2 → 2 → 2 → 2`。**維持稀疏度就是它存在的全部理由。**

### 代價：資訊無法跨越空隙

輸出集合被凍住的直接後果：兩團相距 2 格的點，`ks=3` 的 SubM 疊一百層也永遠不會互相
看到 —— 每層的輸出點都還是原來那些點，中間的空格永遠不會被點亮。

所以真實網路是混用的：主幹用 SubM 維持稀疏度，在每個 stage 交界插一層
**`stride=2` 的規則 SparseConv** 做降採樣。降採樣會把相鄰的東西擠進同一格，順便解決
連通性。這也是為什麼兩種 conv 必須都實作，不能只做 SubM。

---

## 分析工具：offset 集合

四個參數的地位不用逐一討論，壓成一個量就一次判完。SubM 下 `s = 1`（見下），
把配對式改寫成相對位移：

```
offset = in_pos − out_pos = k·d − p
```

跑遍 `k`，得到**每軸的鄰域位移集合**：

```
{ −p, −p+d, −p+2d, …, −p+(ks−1)d }
```

這個集合就是「一個點看得到誰」。SubM 對它有兩個要求：

1. **含 0** —— 否則點看不到自己，中心權重沒有作用對象，`out = W ⊛ in` 退化成純鄰居混合
2. **對 0 對稱** —— 否則鄰域偏向一邊，卷積失去平移對稱性

解這兩個條件：

- 含 0 ⟹ `p = m·d`，某個整數 `m ∈ [0, ks−1]`
- 對稱 ⟹ `m = (ks−1)/2`

```
p = d · (ks−1) / 2        必須整除
```

---

## 四個參數的地位

| 參數 | SubM 下的地位 | 給錯的後果 |
| --- | --- | --- |
| `stride` | **不存在** | 靜默產生語意上無意義的 pair |
| `kernel_size` | 自由，但**必須奇數** | 偶數時兩個條件無解 |
| `dilation` | **唯一真正自由的參數** | —— |
| `padding` | **被推導，不該出現在 API** | 鄰域不置中 |

### `stride`：不是「預設為 1」，是這個概念不存在

兩條獨立的理由：

**語意上** —— `out_pos · s` 的前提是 `out_pos` 活在一個降採樣過的座標系，乘 `s` 才映射
回輸入座標系。但 SubM 的 `out_pos` 本來就是輸入座標。乘 `s` 之後窗口中心落在 `s·o − p`，
而且 `o` 越大偏得越遠 —— `o=1` 偏 1 格，`o=4` 偏 4 格。這不是任何合理的鄰域。

**定義上** —— stride 的用途就是縮小輸出網格；SubM 的輸出網格被定義為等於輸入網格。
兩者直接衝突。

### `kernel_size`：偶數無解

`ks` 是偶數時 `(ks−1)/2` 不是整數，兩個條件永遠只能滿足一個：

```
ks=2, d=1, p=0  →  offsets {0, +1}          含 0，但不對稱
ks=2, d=2, p=1  →  offsets {−1, +1}         對稱，但不含 0
ks=4, d=2, p=3  →  offsets {−3,−1,+1,+3}    同上
```

從另一個方向也會撞到同一堵牆：`ks=2, d=1, p=0` 代進 `out_spatial_shape()` 得
`(5+0−1−1)+1 = 4`，網格從 5 縮成 4，跟「SubM 保持 shape」的定義直接矛盾。
**兩條獨立的推導給出同一個約束**，這是定義自洽的訊號。

### shape 保持是推論，不是額外規定

把 `s=1, p = d(ks−1)/2` 代進規則卷積的 output shape 公式：

```
(x + 2·d(ks−1)/2 − d(ks−1) − 1) // 1 + 1  =  x − 1 + 1  =  x
```

公式自己就吐回 `x`。「SubM 的參數約束」和「shape 保持」是同一件事的兩種說法 ——
不需要在實作裡另外寫一條規則去維持它。

---

## 為什麼是 `d` 決定 `p`，不是反過來

`p = d·(ks−1)/2` 是等式，數學上兩邊誰當自變數都推得出對方。選 `d` 是**設計決策**，
理由有三層。

### 1. 兩個方向的定義域不對稱

反解是 `d = 2p / (ks−1)`。

`d` 當自變數：`ks` 奇數 ⟹ `(ks−1)/2` 是整數 ⟹ **任何正整數 `d` 都給出合法的整數 `p`**，
定義域沒有洞。

`p` 當自變數：需要 `(ks−1) | 2p`，定義域**隨 `ks` 長洞**：

```
ks=3:  d = p        p ∈ {0,1,2,3,…}   沒有洞
ks=5:  d = p/2      p ∈ {0,2,4,…}     奇數 p 無解
ks=7:  d = p/3      p ∈ {0,3,6,…}     只剩 1/3
```

`ks=7, p=1` 沒有任何合法的 `d`。**定義域會隨別的參數長洞的量，不適合當自變數。**

> **`ks=3` 是會騙人的退化情況。** `ks=3` 時 `p ≡ d`，主從關係完全看不出來
> （`d=1→p=1`、`d=2→p=2`）。要看清楚得用 `ks=5`：`d=1→p=2`。本專案的測試目前
> 只有 `ks=3`，讀 code 時別被那組「剛好相等」的參數誤導。

### 2. `p` 在 SubM 裡不是幾何量

規則卷積裡 `padding` 有實體意義：在邊界外補格子，所以輸出網格才變大。

SubM 沒有這件事。輸出座標直接來自 active 集合，**根本不掃網格，邊界從頭到尾沒被碰過**。
`p` 剩下的唯一作用是決定 tap 索引 `k=0` 對應到哪個位移 —— 它是座標原點的記帳項。

而 `d` 是實打實的幾何：它決定這一層看多遠。**自變數要留給承載意圖的那個。**

### 3. `p` 根本不是 SubM 的自由度

把 SubM 的鄰域用它自己的語言寫出來，不借用規則卷積的詞彙：

```
offset = (k − (ks−1)/2) · d
```

先把 tap 索引置中，再乘上間距。**這條式子裡沒有 `p`。**

SubM 的鄰域是 `(ks, d)` 的二參數族。三個符號描述兩個自由度，必有一條約束；
該消掉的是那個**不屬於原始描述**的。`p` 之所以出現，只因為我們把 SubM 塞進規則卷積的
正規式 `in = o·s − p + k·d` 去表達 —— 它是**翻譯的殘留物，不是概念**。

### 具體後果：改 `ks` 時什麼會被靜默改掉

假設反過來讓 `p` 自由。寫了一層 `ks=5, p=2`（⟹ `d=1`，鄰域 `{−2,−1,0,+1,+2}`），
之後只把 `ks` 改成 3：

```
ks=3, p=2  →  d = 2       鄰域 {−2, 0, +2}    中間跳空了
```

`dilation` 從 1 變成 2，感受野的**形狀**變了，而使用者沒碰過任何叫「reach」的參數。

反過來 `d` 自由時，改 `ks` 只會改動 `p`，而 `p` 不可見也沒有語意，沒人會困惑。
**讓被推導的量是那個「改了也不會有人察覺」的量。**

## 對 API 的後果：兩個類別，不是一個 flag

上面的主從關係完全是 **SubM 的置中約束造出來的**，不是 `p` 和 `d` 本身的性質。
規則卷積裡它們是真的正交：

```
ks=3, s=1, p=0, d=3   合法，輸出 x−6
ks=3, s=1, p=5, d=1   合法，輸出 x+8
```

所以：

- `SparseConv3d` 收 `kernel_size, stride, padding, dilation`
- `SubMConv3d` 只收 `kernel_size, dilation`，且 `kernel_size` 必須奇數

**兩者的參數空間維度不同**，這是它們不該共用一個 `subm: bool` flag 的理由 ——
flag 會逼出一個「有些參數在某些 flag 值下沒有意義」的簽名，而那正是型別系統
表達不了、只能靠文件和 runtime 檢查補的東西。

### 上游現況：約束存在，但只存在於 kernel 裡

查證對象是 ROADMAP pin 的 [spconv v1.2.1](https://github.com/traveller59/spconv/tree/fad3000249d27ca918f2655ff73c41f39b0f3127)，
並對照了 v2 master。

`spconv/conv.py` 的 `SubMConv3d.__init__` 收 `stride=1, padding=0, dilation=1`，
**原樣傳給** `SparseConvolution`，沒有任何斷言。v2 的簽章相同，同樣沒有 subm 專屬驗證。

`src/spconv/indice.cu` 的 `create_submconv_indice_pair_cuda` 分派守衛：

```cpp
bool dilation_one = true;
for (int i = 0; i < NDim; ++i) dilation_one &= di[i] == 1;
auto found = false;
if (dilation_one && (NDim == 2 || NDim == 3)) { /* 分派 Kernel2/3 */ }
if (!found) { getSubMIndicePairsKernel<...>(...); }
```

**條件只看 `dilation` 和 `NDim`，`stride` 與 `padding` 沒有出現。**

快路徑 `getSubMIndicePairsKernel3` 的簽章裡根本沒有這三個參數，座標計算寫死：

```cpp
point[0] = indice_data[1] - i + K0 / 2;   // 等價於 p = K/2, s = 1, d = 1
```

慢路徑 `getSubMIndicePairsKernel` 則把三者原樣交給 `getValidOutPos`，**會照做**。於是：

| 呼叫 | 走哪條 | 每軸 offset | 結果 |
| --- | --- | --- | --- |
| `ks=3, d=1, p=0`（**預設值**） | fast | `{−1,0,+1}` | 正確 —— `p` 被忽略 |
| `ks=3, d=1, p=5` | fast | `{−1,0,+1}` | 正確 —— `p` 被忽略 |
| `ks=3, d=1, s=2` | fast | `{−1,0,+1}` | `s` 被忽略 |
| `ks=3, d=2, p=0` | generic | `{0,+2,+4}` | **單邊鄰域**，weight 中心片對到偏移 +2 |
| `ks=3, d=2, p=2` | generic | `{−2,0,+2}` | 正確 |
| `ks=3, d=2, s=2` | generic | 隨 `o` 漂移 | 無意義 |

**同一個 `padding`，`d=1` 時是廢的、`d=2` 時是必填的**，而語意的切換點是一個看似無關的參數。
使用者從預設路徑學到「subm 不用管 padding」，這個結論在他第一次用 dilation 的那天靜默失效。

### 這個約束是承重的，不是潔癖

快路徑只計算一半的 tap：

```cpp
constexpr unsigned center = KV / 2;
if (offset > center) continue;
...
indicePairs(1, KV - offset - 1, oldNum) = ix;
indicePairs(0, KV - offset - 1, oldNum) = gridsOut[index];
```

`(i,o)` 在 tap `k` 成立 ⟺ `(o,i)` 在 tap `KV−1−k` 成立。**這條反對稱性只有在 offset 集合
對 0 對稱時才成立** —— 也就是 `p = d(ks−1)/2` 且 `ks` 為奇數；`constexpr center = KV/2`
更是直接假設奇數。

**上游用來省一半計算量的優化，正好建立在它的 API 拒絕強制的那個不變量上。**
把約束寫進簽章不是加限制，是把已經被依賴的前提說出來。

### 上游為什麼不這樣做（公平的理由）

不是疏忽。`SubMConv3d` 繼承共用基底 `SparseConvolution`，而下游 config-driven 框架
（mmdet3d 那類）用統一的 kwargs dict 按名字建層。簽章一致 ⟹ 換類別名就能替換；
拿掉參數會打破 drop-in 相容性。**那是真實的代價，minispconv 只是剛好不必付**
（沒有 config 生態要相容）。

這是可辯護的差異，不是「上游做錯了」。

### 被否決的方案

**（a）`SubMConv3d` 收下 `stride` / `padding` 但忽略。** 否決。使用者傳了 `stride=2`
以為有降採樣，實際沒有，而且不會有任何訊號。這種「安靜的無效參數」是最難除錯的一類 ——
症狀出現在幾層之後的 shape 上，離原因很遠。

**（b）收下但 assert 等於唯一合法值。** 比 (a) 好，至少會炸。但仍然把一個推導出來的量
放進使用者要填的位置，等於要求使用者自己算 `d(ks−1)/2` 再抄進去。這是把實作的記帳
外包給使用者。

**（c）不放進簽名（採用）。** 代價誠實記下：**與 PyTorch / spconv 的 conv 簽名不一致**，
從 `SparseConv3d` 改成 `SubMConv3d` 不能只換類別名，得刪掉兩個參數。
這個代價是值得的 —— 不一致會在寫程式時立刻被發現（`TypeError`），而 (a) 的不一致
要到訓練跑完才發現。

---

## oracle 該不該擋（尚未定案）

`build_rulebook` 目前對 `subm=True, stride=2` 是**靜默接受**的，會回傳一組數學上自洽、
語意上無意義的 pair。現有測試抓不到，因為所有 SubM 測試都傳 `stride=1`。

傾向的處理：

- **擋 `stride ≠ 1`** —— oracle 的身分是規格，規格對無意義的輸入應該說不，而不是回一個
  看起來像答案的東西。
- **不擋 `padding`** —— `p ≠ d(ks−1)/2` 雖然不是 SubM 的標準語意，但它是個定義良好的
  偏心鄰域。擋掉會讓 oracle 比它要驗證的對象**更嚴格**，而 oracle 應該能表達得更多、
  不是更少。約束屬於 `SubMConv3d` 的簽名，不屬於 oracle。

這條界線值得記住：**規格層拒絕「無意義」，API 層拒絕「不該讓使用者選」。** 兩者不同。
